This report records implementation evidence for the monomorphic data-and-pattern increment and compares it with the informative findings in DN-0007 and DN-0019. It does not define Ash semantics. The normative specification owns the merged language.

Changed composition points

  • The lexer adds uppercase identifiers, _, type, match, |, and =>. The token spelling table is the closed parser-facing join.
  • The retained parser adds declaration, tuple, pattern, and match grammar at its closed assembly points. CST projection verifies each new node and emits ordinary Surface forms.
  • Lexing and event parsing share a 1,500,000-unit syntax-work budget. Each retained token, lexical diagnostic, and parser event is charged before allocation. Exhaustion returns a resource-bearing tree with no partial root; projection cannot admit it.
  • Resolution performs file-wide identity allocation before resolving payload types, then resolves constructor occurrences, patterns, and binder scopes into one registry-bearing program.
  • Type adds nominal and tuple variants. Type admission, provenance traversal, display, registry validation, and coverage are the exhaustive consumers.
  • The retained elaborator, Core arena, independent validator, transforms, and evaluator machine add tuples, constructors, typed patterns, structured matches, and guarded recursive data without a driver-level syntax switch.
  • Evaluation freezes and retains one completed heap. Observation takes the same shared heap, and a structural Value::Data shares it with its root. Scalar and closure results remain ordinary visible values while their result owner retains any locations reachable through a captured environment.
  • Successful orchestration drops the concrete tree after Surface projection and drops the Surface program after resolution. Later stages own every fact they retain, so neither predecessor remains live during elaboration.

What localized

Two-pass type and constructor allocation, expected-type pattern checking, the shared usefulness relation, guarded-root analysis, heap cells, alias handling, and active-path rendering have one implementation owner. Match arms, equational clauses, and local irrefutability all call the same usefulness function. Constructor expressions use ordinary unary application after one registry lookup determines their type.

Match synthesis and checking remain two paths through the same elaboration owner. Synthesis lets the first arm determine the result type. Checking carries the surrounding expected type and its diagnostic cause to every arm, including the first, so checking-only forms do not require a second match representation.

The explicit heap avoided Rust ownership cycles. Recursive data names denote numeric slots; constructor cells and tuple cells contain numeric locations. The 10,000-member cyclic group evaluates, renders, and drops on a 256 KiB host stack. Iterative matching and rendering, rather than recursive Rust ownership, make that boundary possible.

Review hardening aligned parser admission with every downstream pattern and type wrapper. Full-pipeline tests exercise the admitted constructor-pattern, nested-match, multi-pattern equation, tuple-domain header, and synthesized type-wrapper boundaries on a 256 KiB stack. Unchecked Core patterns and registry payloads have independent limits and stack-safe rejection paths.

Coverage uses both a memoized-state limit and one cumulative work budget shared by all usefulness queries in a case group. A 512-constructor exhaustive match is the retained practical-width regression; an 800-constructor group reaches the default budget and reports compiler resource exhaustion rather than a source-level coverage result. Pattern shaping charges each visited tuple and constructor cell before scheduling its children, so repeated conversion of earlier wide rows cannot run outside that budget. A direct 100-arm by 200-field tuple reproduction reached the resource failure at the one-million-work limit in 20.11 seconds with 77,924 KiB maximum resident memory on the environment above. Root and specialized states charge every copied pattern and type cell before allocation. States shared by the active set, memo table, choices, and work frames use one immutable allocation rather than cloning complete matrices. Before syntax remediation, the full-source 100,000-field tuple regression reached the same structured resource failure in 1.47 seconds with 214,144 KiB maximum resident memory; that measurement included its lexer, parser, resolved tree, and partially built Core. A 1,000,001-field source took 12.25 seconds and peaked at 1,945,036 KiB before coverage rejected it. Counting-allocation probes at 25,000, 50,000, and 100,000 fields attributed about 989 requested bytes per field to parser tokens, events, and CST; Surface added 208, resolution added 323, partial elaboration added 231, and transient elaboration work added 432 at the peak. Explicitly releasing the concrete and Surface stages reduced the unbounded million-field probe by about 30 percent but did not provide a bound.

The retained correction charges syntax work before allocation. The 100,000-field case uses about 1,400,040 syntax units, remains admitted to coverage, and now completes in 1.42 seconds with 153,576 KiB maximum resident memory. A temporary 1,000,001-field version of the syntax-resource fixture stopped during syntax construction in 1.68 seconds with 159,280 KiB maximum resident memory, then was restored to its retained 110,000-field width. The structured result renders internal.resource.syntax-work, reports parse.resource, and is not a source rejection. The direct unchecked-Core test keeps coverage resource mapping observable without passing through the source budget.

Registry lookup indexes keep identity lookup independent of declaration width. Core registry closure validation also checks reverse constructor ownership at the constructor identity's source-order index rather than scanning the owning declaration. The 10,000-constructor validates_ten_thousand_constructor_owner_links_without_pairwise_scanning regression completes that path in 0.06 seconds in the environment above.

What necessarily crossed stages

Nominal identity must survive resolution, type equality, constructor typing, coverage, validation, evaluation, and source-facing type display. Tuple shape likewise crosses parsing, typing, constructor payload metadata, pattern checking, application, matching, and rendering. These are semantic facts, not registration data.

The registry now owns source-facing type rendering. It resolves nominal identities to declaration spellings while formatting tuples and arrows with an explicit work stack. Structured argument, binding, definition-result, pattern, operator, and application diagnostics use that rendering. General mismatch values retain their identity-bearing Type members while their textual view uses the same source spelling. Type's registry-free display remains the internal identity view.

The normative static account now exposes the same bidirectional boundary: separate match synthesis and checking rules share pattern usefulness and exhaustiveness, while function and local-binding rules extend their bodies with all bindings returned by one typed irrefutable pattern. The dynamic account enters each guarded data initializer under an explicit continuation and stores its returned constructor location in a separate one-step transition. Derived integer and closure examples bind values directly and introduce no heap allocation beyond the location-bearing data forms.

Constructor-guarded recursion changes group initialization. Function templates alone cannot represent it: all member slots must exist before initialization, data initializers must run in source order, and completed slots alias their constructed roots. Observation must retain the evaluation heap because a cyclic value cannot be copied into an acyclic host enum. The retained returned_closure_retains_the_heap_for_captured_structural_values and returned_closure_observation_retains_its_captured_structural_heap regressions also prove that a closure result cannot discard a heap referenced from its captured environment.

Maintenance mutations

Three deliberate uncommitted mutations tested discoverability in the first candidate implementation. Each was reverted with a targeted patch. The private file named below no longer exists; the results remain evidence about the transferred registry and heap design, not about the retained composition boundary.

Constructor registry accessor

Renaming the candidate Registry::constructor produced four unique missing-method errors: name lookup, payload coverage, witness display, and value rendering. Rust exposed all candidate consumers in one check. In the retained implementation, registry lookups now cross elaboration, usefulness, Core validation, evaluation, and observation rendering; those crossings are named directly in the changed-composition audit instead of treated as a feature-private boundary.

Observed heap contract

Adding one required field to ObservedHeap produced one missing-field error at the sole heap-freezing boundary. This confirms that evaluation-to-observation ownership has one constructor.

Type family

Adding a temporary Type::Probe variant produced six unique non-exhaustive match errors in four files: Core payload admission, elaboration provenance, the shared type display/equality owner, and three data-pipeline consumers. The compiler located the closed semantic joins without a search. The wildcard in the equality decision remained an intentional review point because a new type must not compare equal accidentally.

After reverting all probes, cargo check --all-targets passed. The later shared-pipeline remediation removed the candidate parser, Core wrapper, recursive evaluator, source-text routing, and their public API variants.

Transfer from earlier evidence

DN-0007's central split transferred: tuples are structural, nominal sums use declaration identity, constructors are ordinary values, patterns check against expected types, local bindings require irrefutability, and matches and equations share coverage. Records, polymorphic constructors, and access control did not transfer because the implemented increment excludes them.

DN-0019's simplification rule also transferred. Ordinary application carries payload constructors and higher-order construction. One typed pattern and coverage representation serves three surface contexts. The new facts that could not lower away—nominal registries, structured patterns, and heap locations—remain explicit at validation and observation boundaries.

The recursive-definition evidence correctly predicted the runtime difference: allocate-all-then-check scope transferred, while cyclic constructor data needed preallocation and initialization rather than function templates alone.

The parser rejection corpus covers integer, record, guarded, or-pattern, and other excluded pattern syntax. The type grammar and registry tests admit no parameters, aliases, records, modules, empty declarations, or unary tuples. Core retains structured matches rather than pattern-compilation or decision forms. The heap is private to one evaluation and exposes neither mutation nor stable source-level identity.

Fresh post-review runs of cargo test --all-targets and cargo xtask verify pass at the retained checkpoint. The latter includes formatting, build, warning-free Clippy, all targets, and rustdoc. Changed Markdown passes with the project-approved line-length and repeated-heading exceptions; changed relative links and anchors resolve.

External notation tooling

The repository continues to use readable ebnf and sequent fences with matching prose. The previously recorded lack of an external railroad or sequent renderer remains outside this repository. This increment adds no renderer dependency or conformance claim.
