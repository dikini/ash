Runtime findings

The runtime implementation removes the temporary public gates after adding a private, non-Clone registration owner frame. Non-owning keys associate generated handler and clause frames with that owner. Capture and resume move the owning frame; normal return consumes it. This ownership invariant does not require a global registry to detect an impossible copy of a private owning frame. Stale or duplicated non-owning facts are checked at request and resume transitions. Final runtime reviews and full verification pass.

Three unchanged witnesses identified corrections during this increment:

  • Callback-environment preparation originally happened after capture. A failed extension left one frame instead of the original two. Preparation now precedes capture; the owning preflight test passes without consuming control or changing registration counters.
  • An imported callback with latent row {| R} under a signature containing {Adjust<Int> | R} checked at source but failed independent Core validation. Generated application lowering omitted the already-authorized lacks fact. It now uses ordinary row qualification and explicit application emission, preserving the least row and the existing independent authority check. The unchanged imported callback test passes through both transforms.
  • Direct internal discard of a generated registration clause initially returned success. The clause's existing registration association now rejects that transition before consuming its capture. The full gate reruns this witness and the distinct permitted subscriber-local discard case.

An additional resume association scan was removed by reusing the existing clause lookup, preserving ordinary hook-free resume work. No callback variant restriction, new effect-row authority or second evaluator was introduced.

Independent semantic review found a defensive gap: return and resume must reject an extra active non-owning handler for the same activation before changing owner state. The existing charged scan can require one active handler at request selection and zero other active handlers at return/resume. Both transitions independently returned success in the failing witnesses. The shared scan now enforces those exact counts, and both unchanged witnesses pass. No additional scan or registry was added. Semantic re-review and the complete corrected regression gate pass.

Registration-specific generic coincidence controls now execute through both transforms. Equal and unequal instances produce 42 and 1 with a callback-added dependency's cell still live; the equal escaping result rejects. Completion controls resume with 4 and 3, while both discard variants reject because both retain registration completion. No unequal escaping success or summary-erasure precision is required. An older ordinary handler returns 30 to the registration callback, which produces 31; this complements the publisher-side interception case. These controls and the complete corrected gate and reviews pass.

Owning resource evidence

The owning tests retain measured work rather than an estimated allowance:

  • hook_identity_retention_is_exact_and_disposes_failed_deep_inputs in resolution checks generated identity retention.
  • hook_body_and_identity_elaboration_are_exact_and_fresh_retryable in elaboration checks all shorter allowances with two phantom target arguments and a tuple.
  • hook_root_validation_is_exact_one_short_and_retryable in Core validation measures the root handler check, rejects one-short work and repeats two fresh exact allowances.
  • nested_hook_recompute_owns_partial_target_clones in Effect Core puts a 32,000-node left-associated application spine before a second phantom argument. Its failure cutoff is measured prefix work plus one extra range slot, one hook-node charge, two argument slots and the complete first clone. The unchanged cutoff originally overflowed during partial-clone disposal; it now reports exhaustion and restores retained rows. Separate full-work calibration checks one-short rollback and two fresh exact retries on a 256 KiB child stack.

The safe target clone charges argument slots before cloning, retains partial arguments in iterative owners, then charges and reserves final argument slots before transferring ownership. Nested roots use this path without changing ordinary-handler work accounting.

nested_root_pipeline_and_disposal_fit_a_small_stack checks 24 roots on a fresh 256 KiB thread through direct loading, resolution, module checking, linking, validation, evaluation and disposal. This follows the resource predecessor's helper pipeline. It does not establish the same bound for the full run_path wrapper: the matched resource control also overflowed through that wrapper. No predecessor depth or resource ceiling was relaxed.

Registration resource tests add:

  • registration_retention_is_exact_and_disposes_failed_deep_inputs in resolution, including 32,000-node inputs.
  • registration_body_callback_and_owner_elaboration_are_exact_and_fresh_retryable in elaboration, covering every insufficient allowance and two fresh exact retries with an anonymous callback.
  • registration_capture_work_is_exact_one_short_and_retryable in Core validation, measuring the actual finite proof rather than assuming a fixed allowance.
  • Three 4,096-depth/256-KiB failure witnesses in elaboration: registration_contextual_function_disposes_deep_payload_when_provenance_budget_fails, registration_callback_check_disposes_first_deep_clone_when_second_clone_fails, and registration_lowering_disposes_deep_result_when_resume_row_budget_fails. Each retained failure originally overflowed during recursive type disposal. Existing iterative owners now retain partial types until transfer.

The lowering witness uses the actual lowering function and a synthetic deep intermediate body. Its unbounded control rejects Core admission after 16,439 elaborator work units; 16,438 units fail at the preceding resume-row clone. It never constructs a successful invalid Core program. This one direct lowering RED/GREEN, the same inspected guard at five fallible windows, exhaustive shallow budget tests and existing deep owner-disposal evidence establish the shared ownership correction. It is not five separate deep reproductions. Structural depth limits do not bound all host ownership depth: type-application left spines can remain deeply owned after admission.

registration_pipeline_and_disposal_fit_a_small_stack checks 24 registrations and an outer root through direct loading, resolution, checking, linking and independent proof on 256 KiB. Its original helper overflowed, as did a matched root-only helper. Aligning with the accepted direct root harness retains source, depth, stack and compiler phases; this is not an unchanged-helper success or a runtime test. A later contextual-typing correction regressed this unchanged witness. Extracting ordinary binding scheduling verbatim reduced the measured shared frame from 109,152 to 106,944 bytes and restored both root and registration witnesses without further harness or limit changes.

Runtime resource evidence

Owning machine tests measure registration work separately from the compiler ledgers above. Acquisition charges 3 + environment.len() before retaining two frames and their callback relation and looking up the callback. Each owner-association scan charges the active frame count before traversal. Generated resume additionally charges its captured frame count for association checking; restoration preflight charges that count when registrations are live. Ordinary request search and callback evaluation retain their existing work. These are charged traversal bounds, not a claim that every publication has one fixed total cost.

registration_publication_work_is_exact_one_short_and_fresh_retryable measures the complete evaluator ledger for the two-registration program, rejects one less and repeats two fresh exact runs. Acquisition separately has the same boundary controls. registration_chain_steps_are_separate_from_ordinary_callback_work uses chains of 1, 2 and 4 registrations with callbacks containing either one or four primitives. A chain of N has N acquisitions, N+1 requests, selections and resumes including the root, and N times the callback's primitive count.

Capacity tests lower the owning machine's limit to one or two entries. They distinguish active and captured owners, reject one-short capacity, repeat exact runs and reuse released capacity with fresh keys. Registration capacity is separate from cell capacity; both default to the existing representable-frame bound. Counter overflow, missing binding and failed work preparation publish no partial acquisition. Invocation preflight preserves the original frames, capture count and registration state on failure.

deep_registration_callbacks_capture_cells_and_dispose_failure_on_a_small_stack compiles a recursive source fixture before entering a fresh 256 KiB thread. Evaluation on that thread acquires 1,025 registrations and cells, invokes each callback once, and returns the sum of depths. Two fresh bounded runs fail at the first callback's Pause request and dispose pending control, owners and environments on the same small stack. This is runtime success and failure evidence, not compilation of that fixture on a small stack. Separate compiler witnesses retain their stated 24-scope bounds.

Actual stale and duplicate non-owning handler transitions are tested without copying the private owning frame. Independent Rust review additionally found that clause return must compare retained clause associations with its pending count before mutation. Its unchanged witness first returned success, then passed after adding that comparison to the existing scan. The check accounts for the popped clause at return, preserves state on rejection and permits the original clause and owner to complete afterward. Source re-review confirms the invariant, and the corrected full gate passes.
