Simplification disposition

No carrier, validation pass or runtime owner was found removable within this bounded audit without weakening an existing obligation:

  • Shared nominal/row/type operations avoid separate semantic type systems. Static identities, activation keys and ownership frames have different roles.
  • Module callable summaries support separate checking; final Core capture analysis independently reconstructs actual linked dependencies. Cleanup-row inference computes results that later safety validation checks.
  • Registration ownership must survive periods when its generated handler is inactive, preserving pending callbacks and release authority during forwarding.
  • Pure and Effect share one explicit evaluator. Pure creates no live effect owners or handler/continuation frames, but the machine contains zeroed effect accounting fields and shared evaluator-local disposal observation. No claim of an effect-free physical layout is made.
  • Native ownership reuses resource scope, capture and disposal. No general provider registry, scheduler, replay mechanism or authority calculus is added.

Similar clone helpers have different staging and work accounting. Consolidation without a new concrete need and resource-bound evidence is not a justified closure refactor.
