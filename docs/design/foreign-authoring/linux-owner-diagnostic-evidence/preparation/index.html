All design notes

Status: PREPARATION ONLY. No image or owner/native process has run. Root has accepted the exact reviewed residual premises as trusted assumptions for one bounded existing-profile diagnostic, not an ownerful AD, strict checked runtime approval or execution assignment. Readback records that separation. Proposal binds the exact image, static receipt, proposed premise, policy, harness and source-derived rendering.

The fresh harness adapts the separately reviewed scalar harness with a visible diff: owner 128 MiB / PH 64 / receipt 256 KiB / approval 64 KiB / output 16 KiB / deadline 30 seconds, exact malloc/free image/receipt/premise, new purpose/context/mode and no old scalar or reporter approval. The old source, policy and tests remain unchanged. Context is the explicit trusted manual operator host-authority/empty-env/fixed-fd experiment association; it is not a product store/namespace/credential authentication claim. Final independent root approval must bind that exact context and all artifact hashes. No valid approval file is created here; test approvals exist only in memory under fork/exec guards.

Before child creation the harness admits bounded regular controls without following links/FIFO blocking, matches approval/receipt/policy/premise, makes a bounded private copy, copies to explicit executable memfd flags 19 / mode 0500, seals write/grow/shrink/seal changes, then hashes/inspects the final immutable fd. It rechecks exact approval and sealed hash/seals before executing that same fd, fixed single argv0, empty environment, stdin/dev/null and one bounded output pipe. The child maps image FD 3 and standard FDs and closes unrelated FDs 4 onward. No image pathname is reopened for execution. The copied pathname is deliberately tampered after pinning; changed-path admission refuses and original sealed object stays unchanged. No old executable replacement is reused or executed.

The inherited cleanup covers all post-fork parent setup, timeout, overflow and refusal paths. It persists pending before SIGKILL/waitpid and reports success only after actual reap and EOF. Output arriving after reap is still drained and checked. Kernel waits can delay; 30 seconds is a termination-request deadline, not guaranteed timely kernel reclaim. This trusted program has no authored process/thread creation; direct-child cleanup is not descendant/hostile process containment, fault injection or isolation. Reaping does not prove native free.

Expected rendering derives exact Completed(8, Closed) plus newline for the intended acquired path and NotAcquired(()) plus newline for possible nullable refusal. Null is recorded as non-acquired, not intended diagnostic success. The read is stored source data 8, not native memory. Neither output proves destructor internals/native truth or checked O/K/groups.

The exact isolated-Python safe test command ran 14 methods and passed, with harness/policy/tests/interpreter/old originals frozen before=after. Fork/exec are globally prohibited by the runner and mocked within lifecycle controls; no actual child or candidate bytes are used. The real memfd/seal/mutation control uses synthetic 120-byte ELF-shaped data only. Controls cover bounded/FIFO/duplicate input, approval/receipt/premise/mode/context mismatch, descriptor/empty-env contract, copy tampering, sealing, pre/postfork setup, interrupted wait/deadline, output overflow and late output after reap. These mocks validate the state machine, not a real new-child termination result.

Sandbox EACCES, any nonzero/signal, timeout, unexpected output or missing reap must remain actual refusal records. No automatic host rerun or fallback exists. A separately authorized normal-tool host escalation must preserve the exact approved artifacts and sandbox record; it is not a policy/credential change. Root per-image approval, independent exact review and explicit execution assignment remain required. Known runtime-loading uncertainty/native memory/ allocator/error/unwind/shutdown/host-loss assumptions are diagnostic premises, not no-loading proof, ownerful architecture, checked runtime or whole F2 success.

These notes record research, alternatives, and evidence at the source revision linked above. Their status is preserved in each document.
