Owner packaging observations and proposed map-only budget

Development design notes · ash-lang 67c79dd

Informative design work. Proposals and experiments may be incomplete or superseded. Read the language specification for current rules.

All design notes

Informative F2 experiment evidence for issue #58. This delivery proposes only the map budget amendment. It records selected-source compiler production, ordinary legacy owner-host generation and two static-relink refusals. No static candidate has passed inspection or started. No ownerful architecture, checked runtime, deployment, store/context, isolation or whole F2 acceptance follows. AD-0015 stays owner-free.

Inputs and correspondence

The selected compiler source is commit 1a8ecef0b03ddc75a45254543bd8f6f0bb10969c, tree e4ab5e35b50d64326e548fc54cf264a4af170832. The complete selected manifest pins all 2784 blobs (96,452,672 content bytes). Its 177-input build.rs runtime census is separate. Each successful build phase verified complete snapshot and its declared tool/configuration inputs before and after. The original contract bytes, SHA-256 27430b69ee44dcbcb835a83dc38ff2b034826b81dddae40b7bb9ba7b4377cc3e, were retained by PR100 at 2ac8c393846715249de5a475a65e47bf1309bb54. The proposed new map budget does not rewrite that contract or the old assignments.

The adapted owner changes only the two native symbol names to malloc/free; the entry requests one eight-byte opaque allocation. Its read returns independent stored input 8; it does not read native memory. This is the legacy direct-resource baseline, not PR97's static checked lifecycle. No Borrow/current-window or C-to-S extension is introduced. The generated root source, Cargo manifest, post-resolution lock and generated inventory retain actual associations. The initial lock seed comes from selected-source embedded-write correspondence; it was not independently captured as a generated pre-Cargo file. Internal Cargo may resolve that seed before public build returns.

Why the prospective map-only change

Attempt Observed map size at refusal Exact retained prefix Prefix content
Default 17,346,560 bytes 16 MiB prefix Discarded sections starts at byte 519242; no active-map/LOAD/OUTPUT marker
No discarded diagnostics 17,674,240 bytes 16 MiB prefix Active map at 519386 and LOAD at 519416; no OUTPUT marker

These are sampled oversize observations, not complete-map sizes. Neither raw oversize external map was fully hashed or declared complete. Each prefix hash is a hash of exactly 16,777,216 retained bytes, not of the whole map. The diagnostic-option provenance records the pinned installed BFD manual and its short relevant excerpt: --no-print-map-discarded suppresses discarded/garbage-collected map listings. That suppression worked, but the remaining active map still exceeded 16 MiB. No option changes source, native bindings, ABI contracts or executable semantics. The exact relink uses cc plus explicit -fuse-ld=bfd, not rustc's default LLD.

The proposed 64 MiB allowance applies only to a complete new map. Logs and command output stay at 16 MiB; all other bounds and existing framing, LOAD and pinned libc.a gates stay unchanged. The executed monitor has a shared watched-file limit and cannot yet express that split. A future exact tuple needs independently reviewed per-class enforcement/retention, fresh paths and source/tool checks. Sampled observations can overshoot or miss intermediate changes; they are not hard quotas or proof of an unobserved peak. This delivery changes no monitor, collector or executed command. It does not assign another attempt.

Retention and verification

The retention index maps every original execution-inventory record to its exact retained path or explicit omission. The four original execution manifests are retained unchanged and may refer to omitted external files; they are not inventories of this compact publication. Historical README and contract bytes use .txt suffixes to distinguish original path-relative records from the current documentation. Each map prefix is stored once, shared by its original inventory and this index. The second prefix contains original trailing spaces and neither prefix ends in a newline. Preserve those raw bytes; whitespace checks on authored prose exclude exact captured records. This is an evidence exception, not source formatting permission.

No compiler/host/private binary, cache, source archive, system header, full map or obsolete preparation generation is copied. Missing original artifacts and absolute /tmp paths limit reconstruction; a receipt/hash alone cannot recreate them. Other shared-cache builds may replace historical outputs. The selected archive and full source remain external, associated by the existing complete manifest. New observations need a fresh reviewed assignment; copied records are not newly executed results. Original producer receipts and both failures remain unchanged. Dispose of external failed maps/generated roots only after independent evidence review; preserve useful shared cache under the current sole operator.

The publication manifest binds this subtree and both informative document changes. The staged verification checks copied-original equality, manifest membership/hashes, UTF-8/JSON/Python syntax, relative links and read-only patch application against the stated base. No Cargo, compiler, linker, readelf, owner image, benign child or native probe is run during this documentation work. The historical tuples/configs are evidence, not reproduction commands to execute.

Header/ABI correspondence, a complete inspected static candidate, native/runtime loading and shutdown premises, ownerful architecture review and a fresh exact startup approval remain pending. F4 O/K reservations/quarantine/completion, F6 immutable receipt/approval/store/context enforcement, checked runtime/image activation, C-to-S/SQLite and F7 isolation/credentials/storage/filter/quota/fault/ termination evidence remain separate obligations. All whole-scope F2 criteria remain open.

Later 64 MiB refusals and prospective follow-up

The later map-budget evidence retains the next two actual refusals, bounded source/metadata analysis and exact compressed prefix content. Its proposed 128 MiB map-only/output-placement amendment grants no retry, monitor/tuple or startup authority and changes none of these earlier records.
