This directory is the canonical Ash specification. It is normative and describes exactly the implemented language and runtime behavior.

Current Ash

The current dialect is ffi-ash. It includes the implemented foreign-call, generic-cell, lexical-region, retained-control and pinned-worker features below. The name identifies the current language on main; it adds no compiler mode or compatibility grammar. Earlier milestone tags retain their original contents.

Ash is a rank-1 language whose programs are acyclic graphs of passive source modules. Each .ash source file defines one unnamed module containing imports followed by nominal data or newtype declarations, method-only interface declarations, effect declarations, anonymous implementation declarations, foreign-library declarations, and global function definitions. Global signatures may state explicit interface constraints and latent effect rows, and implementation heads may state explicit prerequisite constraints. A module has no result expression, runtime module value, or initialization.

Imports expose only public facts. A private complete import places a dependency's public namespaces under a module alias. A private targeted import places selected public spellings in the importing module's file-wide namespaces. A public import must be targeted and re-exports its selected spellings. These name channels preserve the defining declaration identities.

An impl Interface item is an independent channel. It binds no source name and makes the dependency summary's public implementations for that interface available for evidence selection. Neither a complete import nor a targeted name item selects implementations. A public implementation item also adds the selected facts to the importer's public implementation closure, so later facades can select them transitively without changing their defining identities. Private nominal identities may flow through public schemes and implementation facts without becoming nameable. A pub opaque type exports a name without constructors, and a pub type exports its name and complete constructor family. The corresponding newtype visibility modes use the same name and constructor access rules.

A module newtype introduces a nominal type over one representation. It has exactly one same-spelled, one-field constructor. Construction and matching are explicit, and the nominal type remains distinct from its representation. After independent Core validation, wrapping and unwrapping erase without a wrapper allocation or runtime tag. Interface evidence remains nominal: an implementation for the representation does not satisfy a requirement for the newtype.

A local newtype introduces one compile-time lexical identity for the following declarations and result of its block. Its representation sees the preceding type scope; later declarations may shadow the nominal and constructor names together. The identity cannot escape in a type, effect row, scheme, or requirement. A closure may capture and unwrap a local value when its exposed computation contains no such identity. Execution creates no fresh identity or scope state.

A sequential local with supplies exact interface methods for a complete application whose selection key contains an active local nominal. It is not local implementation search. Supplied methods capture preceding ordinary values; the evidence is available only in the following lexical remainder. Selected methods lower to ordinary functions, and checked closures may retain them after that evidence block returns without exporting the evidence itself.

Ordinary construction uses lexical region storage. region<R> r [= provider] establishes one owner with a fixed ordinary allocate/release pair; omission uses the host-backed default. using r { body } selects live access for fresh construction without ownership transfer or relocation. Values and actual captures retain their residency/dependencies, and required cleanup finishes before the original paired release bulk-reclaims that region. Ordinary blocks/calls create no region. Function records are created once; fresh call-body construction uses the caller's selection. Ordinary source value-function arrows include the default allocation requirement even when their written row is empty; extra provider effects remain visible. Core retains these requirements and controls explicitly.

An interface declares one or more ordered, fixed-kinded type parameters and an ordered set of method signatures. It may declare one total forward determination edge from a nonempty parameter key to the entire dependent complement. A method may bind an explicit ordered list of fixed-kinded local parameters, and every method value type has Function as its top-level constructor. Each occurrence instantiates the complete interface vector and the method parameters, while only the complete interface application creates an evidence obligation. Its methods are constrained terms. An implementation supplies the complete method set for one complete interface application but introduces no source name. Private implementations remain available only in their defining module; pub impl publishes a body-free fact that dependents or later facades may select explicitly. Body-free summaries preserve canonical interface parameter and determination records, complete applications, method schemes, and their defining identities.

Ash's monomorphic kind language contains Type, EffectRow, and right-associative function kinds such as Type -> Type. Declaration parameters may state their kinds. Every omitted declaration kind annotation and every binder introduced by an omitted implementation binder list is fixed to Type. An omitted global binder list discovers ordinary free type variables and effect-row-tail variables in their shared first-occurrence order. A name occurring only in ordinary type positions has kind Type; one occurring only as an effect-row tail has kind EffectRow; using the same name in both roles is invalid. Ash does not infer a function kind from use. This is a phase-dependent constraint, not a commitment against later bounded declaration-local kind inference. A type constructor or parameter may remain bare or partially applied when its resulting kind satisfies the context that owns the type.

An effect declaration defines one module-owned API with one or more operations. Function computations carry rows of exact, parameterized effect identities. perform requests an operation, and an exhaustive lexical handle removes one exact instance. Each selected clause must consume its non-escaping continuation capability exactly once on every normally completing path. An ordinary clause uses resume or checked discard. Discard closes the selected capture and recursively owned live captures in structural order, then continues the clause with Unit. Inference proves safe closure without skipping outside or running completion owners. Its effect row includes invoked cleanup actions.

@builtin.retained_control provides a scoped Store and opaque non-owning keys. A private handler associated with that Store may consume its selected clause owner by retain or resume. A later admitted consumer can continue a live key once; the restored branch returns to that consumer and may yield a fresh key. Actual captured support and interpreter identity remain checked. Store release requires its retained and active branch work, including cleanup, to be complete; an observation from Probe establishes quiescence only when the Store is selected and the observation remains current. Ordinary library code can choose and drain work without adding a scheduler primitive or a fairness or termination guarantee. The static and dynamic rules specify these relationships.

@builtin.network provides a scoped pair of pinned worker executions and copied FIFO byte channels. Worker entries are closed named functions; their local Stores retain ordinary resource and completion rules. Transport End, worker return and backing settlement are distinct. The static and dynamic rules describe the boundary; Work/Ack and its errors are ordinary Ash code.

A passive foreign library declares a target profile and symbols with source signatures and C link names. Each symbol is an ordinary effect with one call operation. Imports preserve its defining identity and perform no native work. Ordinary source handlers may handle these operations; generated linked hosts supply native interpretation for the remaining required symbol effects.

@builtin.foreign supplies opaque nominal Address and pure null, is_null and equal functions. Address transports a C data pointer, including null, without an integer conversion. Equality compares pointer values and proves neither allocation identity nor validity. Copying an Address creates no ownership, lifetime or resource dependency. There is no constructor, arithmetic, dereference, memory-copy or freeing primitive.

Whole Unit arguments map to no C arguments; whole Address or Bytes arguments map to one pointer. Flat tuples of Address/Bytes map to pointers in source order. Address results map to pointers and Unit results to actual C void. Bytes is argument-only. Numeric slots, out-pointers, nested tuples, Unit tuple components, callbacks, variadics and structs by value are unsupported.

A Bytes argument exposes its immutable backing through a readonly pointer held through the synchronous call. There is no hidden length, NUL terminator or encoding conversion; empty Bytes promises no readable byte. Native code must not mutate or free managed backing. If it retains or returns the pointer, the binding module must keep the original Bytes alive for every later native use. An Address result does not retain or infer that relationship.

Bindings express checks, conversions, null handling and cleanup in ordinary Ash. The declaration assumes the native signature and behavior; the compiler does not verify them. Existing handlers and scoped cleanup govern ordinary completion, capture and checked discard. No Address-to-Bytes/String or arbitrary memory read/write API is supplied.

@builtin.generic_cell supplies Cell<R,T> for one fixed ordinary payload type. Acquisition owns a mutable slot and release; access handles are non-owning. Reads return snapshots, writes replace the current value, and dependency checks reject self-retention, younger retention and resource-owner cycles. An independent snapshot may escape its cell; a live reader cannot. Exact source handlers retain ordinary precedence. The static and dynamic rules specify this API.

The legacy resource cell<R> c = initializer { body } acquires one scoped mutable integer cell through the compiler-owned @builtin.cell API. The scope owns release; handles provide reusable access while it remains live. Inferred dependencies prevent handles, captured access and identity-indexed operations from escaping their owner, including through request payloads. Copied integers may escape. Each execution has a fresh activation, and capture/resume moves the owned scope without duplication. Normal completion or owned abandonment releases it once.

hook H { body } supplies the empty identity chain for an exact effect API with one endomorphic publish operation. register H transformer { body } evaluates one ordinary transformer and retains it for that scope. Publication uses perform H.publish value; outer registrations transform before inner ones, and callbacks run under handlers surrounding their registration. An exact nested root starts a separate chain. Normal return removes each registration once; capture/resume preserves its owner. Owned abandonment removes it without running its transformer or remaining publication callbacks; discard cannot skip required outside completion. Callback effects and stored resource dependencies remain checked.

cleanup action { body } evaluates and retains one Unit -> Unit action. Normal completion invokes it, then returns the saved body value unchanged. Capture/resume transfers the invocation owner; copies of the callable gain no cleanup authority. Owned abandonment invokes actions under the surviving context with needed live resource handlers. Ordinary source handlers removed by the cut are not restored. Required removed interpreters reject at each action's closing position. An executing action and its unfinished close operation remain required completions and cannot be discarded. Action effects and stored dependencies remain checked. Ordinary typed reporting can retain ordered cleanup failures separately from the body outcome; constructors have no implicit failure meaning. Internal termination or exhaustion provides no source-cleanup guarantee.

The source path selected for execution is the entry module. It declares exactly one local, monomorphic, unconstrained main : Unit -> R, where R is closed. Its computation row is closed and contains only the default allocation requirement and required admitted native symbol effects. After checking every dependency, Ash links the module groups and evaluates main () inside an explicit host-backed root, established before module closure construction. That root and required native interpretation discharge the complete outward row. Imports, exports, aliases, and opacity are static access rules and do not remain as runtime operations. Interface identities, implementation identities, and their checking registries also erase. Selected evidence lowers to ordinary functions, applications, and dialect-specific type operations. Pure erases instantiation; Effect retains lexical instantiation for exact operation matching across generic calls and returned closures. Evaluation has no runtime module object, implementation registry, interface lookup, or handler registry.

Ordinary source value positions remain rank-1. No source annotation denotes a nested scheme. Source code cannot write forall or expression type arguments; give a parameter, result, tuple field, or constructor field a polymorphic annotation; store or return an uninstantiated method scheme; pass one to an ordinary parameter; add implicit method binders or method requirements; or use polymorphic recursion. Core admits a nested scheme only where authenticated compiler-generated method evidence requires it. Every other source value position remains monomorphic; the internal lexical polymorphic functions retained by Effect execution do not make schemes first-class source values.

Determination adds no associated-output syntax or projection, multiple or partial edges, proposition or proof evidence, common universal evidence, or existential pack and unpack form.

Module and local newtype add no runtime-fresh identity, implicit coercion, general representational equality, local implementation, effect or resource mechanism, existential package, dynamic loading, runtime nominal registry, heap-inspection API, special value rendering, or general ABI or foreign-representation guarantee. Its canonical conversion establishes no interface, proof, provider, handler, or hook authority.

Within a module, Ash provides global and explicit local recursion, rank-1 polymorphism, nominal data, allocation-free module and local newtype, structural tuples, constructor values, typed patterns, exhaustive matches and equations, sequential bindings, method-only interfaces, explicit constraints, anonymous implementations, and pure and effectful expressions with single-use, non-escaping handler continuations.

Beyond the fixed builtin providers and the bounded source-resource forms described above, the effect kernel adds no general provider or resource declarations, first-class registration tokens, arbitrary removal or priorities, general destructor declarations, first-class continuation values, multi-shot resume, worker migration, shared-Store scheduling, or dynamic loading. Scoped retained control and the fixed pinned-worker network are implemented as described above. A linked row left nonempty after generated root and native discharge is a source rejection rather than an unhandled-operation runtime result.

Module examples

The following two sibling files form a complete program. main.ash imports ./arithmetic.ash under the alias Arithmetic:

import arithmetic as Arithmetic

main : Unit -> Int
main () = Arithmetic.answer(())

arithmetic.ash exports only answer:

pub answer : Unit -> Int
answer () = 42

Kinds and higher-kinded parameters also cross module boundaries. This dependency.ash file exports a kinded interface, an implementation for the bare Option constructor, and a global whose explicit parameter has kind Type -> Type:

pub type Option<A> =
    None
    | Some(A)

pub interface Observe<F : Type -> Type> {
    observe : F<Int> -> Int
}

pub impl Observe<Option> {
    observe value = 40 + 2
}

pub relay<F : Type -> Type> : F<Int> -> F<Int>
relay value = value

The sibling entry imports the nominal, constructor, constrained method, polymorphic global, and selected implementation fact:

import dependency (Option, Some, observe, relay, impl Observe)
main : Unit -> Int
main () = observe(relay(Some(1)))

The dependency summary carries the defining identities and fixed kinds without the dependency body. Linking authenticates the selected Observe<Option> evidence before Core synthesis. The program observes 42 : Int; kinds and selected interface evidence introduce no runtime lookup or module value.

A targeted import can select and rename that export without introducing a module alias:

import arithmetic (answer as imported_answer)

main : Unit -> Int
main () = imported_answer(())

Module newtypes

This complete module wraps and unwraps a distinct nominal UserId. The wrapper has the integer representation at runtime, so the program observes the value 42 while retaining the result type UserId:

newtype UserId = UserId(Int)

increment : UserId -> UserId
increment (UserId value) = UserId(value + 1)

main : Unit -> UserId
main () = increment(UserId(41))

The executable test overview_module_newtype_example_is_executable checks this example. Neither constructor use is an implicit conversion, and an importer may use the constructor only through a transparent authorized route.

Local newtypes

This complete module returns a closure that captures a local representation, then calls it after make returns. The closure exposes only Unit -> Int, so the program observes 42 : Int without exposing the local identity:

make : Unit -> (Unit -> Int)
make () = {
    newtype Offset = Offset(Int)
    let offset = Offset(41)
    fn(ignored) {
        match offset {
            Offset(value) => value + 1
        }
    }
}

main : Unit -> Int
main () = make()()

The executable test overview_local_newtype_closure_example_is_executable checks this example. Local declarations are sequential and private; they do not add local implementations or implicit existential packages.

Scoped exact evidence

This complete module supplies the relation Read<Token, Int> for a local identity. The supplied method captures saved; forward receives its ordinary method function through the existing constraint mechanism. The result is 42 : Int:

interface Read<A, B> where A -> B {
    read : A -> B
}

forward<A, B> : A -> B where Read<A, B>
forward value = read(value)

main : Unit -> Int
main () = {
    newtype Token = Token(Int)
    let saved = Token(41)
    with Read<Token, Int> {
        read ignored = match saved {
            Token(value) => value + 1
        }
    }
    forward(saved)
}

The test overview_scoped_evidence_example_is_executable checks this example and the direct read(saved) variant. Abstract requirements and exact-current implementation evidence precede lexical evidence; lexical evidence precedes concrete implementation matching. This form introduces no resource lifetime, proof authority, acquisition, or existential package.

Interfaces and selected evidence

An interface method can use a local implementation without changing the entry contract. This complete module selects Equal<Int> at the call to equal and observes true : Bool:

interface Equal<A> {
    equal : (A, A) -> Bool
}

impl Equal<Int> {
    equal (left, right) = left == right
}

main : Unit -> Bool
main () = equal(1, 1)

Constraints also cross module boundaries through checked public declarations. In the following sibling-file program, main.ash uses a complete import for qualified names and a separate targeted item for implementation evidence:

import equality as Equality
import equality (impl Equal)

main : Unit -> Bool
main () = Equality.same((1, 1))

The defining equality.ash exports a method-only interface, a constrained global, and an anonymous implementation fact:

pub interface Equal<A> {
    equal : (A, A) -> Bool
}

pub impl Equal<Int> {
    equal (left, right) = left == right
}

pub same : (A, A) -> Bool where Equal<A>
same pair = equal pair

The body of same uses its declared requirement. At the imported call, ordinary typing fixes the argument to Int, and the explicit selector makes the defining module's public implementation available. The program observes true : Bool.

A targeted public import can place a facade between that implementation owner and the entry. This complete facade.ash re-exports names and implementations through independent items:

pub import equality (Equal, equal, impl Equal)

The facade entry selects the same channels from facade.ash:

import facade (Equal, equal, impl Equal)

main : Unit -> Bool
main () = equal(1, 1)

The selector follows the facade's public authorization route to the implementation defined in equality.ash. The interface, implementation, method, and binder identities remain those of the defining module. Aliases and authorization routes do not become runtime values; the selected method evidence runs as ordinary function application.

Polymorphic method evidence

One constrained global may use the same method scheme at unrelated instantiations. This api.ash module exports a higher-kinded interface whose method binds two local type parameters, then uses it once from Int to Bool and once from Bool to Int:

pub interface Functor<F : Type -> Type> {
    map<A, B> : (A -> B, F<A>) -> F<B>
}

to_bool : Int -> Bool
to_bool value = value == 42

to_int : Bool -> Int
to_int true = 42
to_int false = 0

pub map_pair<F : Type -> Type> : (F<Int>, F<Bool>) -> (F<Bool>, F<Int>) where Functor<F>
map_pair (numbers, flags) = (map((to_bool, numbers)), map((to_int, flags)))

The sibling carrier.ash module reuses the defining method identity and publishes a generic implementation for Box:

pub import api (Functor, map)

pub type Box<A> = Box(A)

pub impl Functor<Box> {
    map (function, Box(value)) = Box(function(value))
}

A total determination edge permits a dependent parameter to occur anywhere or nowhere in a method type, while every determinant must occur. Improvement uses an inference-free key to fill the whole dependent tuple before complete- application evidence selection. This program determines Result as Unit from the Bool key even though Result is absent from measure and observes 42 : Int:

interface Measure<Key, Result> where Key -> Result {
    measure : Key -> Int
}

impl Measure<Bool, Unit> {
    measure value = 42
}

main : Unit -> Int
main () = measure(true)

The entry.ash module imports the constrained global and explicitly selects the implementation:

import api (map_pair)
import carrier (Box, impl Functor)

main : Unit -> (Box<Bool>, Box<Int>)
main () = map_pair((Box(42), Box(true)))

The program observes:

(Box(true), Box(42)) : (Box<Bool>, Box<Int>)

The method scheme is authenticated across both source-body-free summaries. Concrete evidence uses one generated adapter over the implementation method. This Source program uses Effect execution, retaining lexical instantiation and once-created records through the ordinary evaluator rules. Pure Core retains its separate type-erasure rules. The source filename retained by the test corpus is interface.ash, but the executable tree stages that content as api.ash because interface is reserved in a module path.

Opaque types and smart constructors

An opaque type is nameable in an importer, but its constructors are not. This token.ash module keeps construction and matching inside its boundary:

pub opaque type Token = Token(Int)

pub make : Int -> Token
make value = Token(value)

pub step : Token -> Token
step (Token value) = Token(value + 1)

pub read : Token -> Int
read (Token value) = value

An importer may name Token.Token in an annotation and compose the public operations. It cannot use the Token constructor in a term or pattern:

import token as Token

main : Unit -> Int
main () = {
    let token : Token.Token = Token.make(41)
    Token.read(Token.step(token))
}

Hidden carriers

A private type can occur in public function schemes without exporting its source name. In carrier.ash, the identity shared by make, step, and read remains consistent for importers:

type Hidden = Hidden(Int)

pub make : Int -> Hidden
make value = Hidden(value)

pub step : Hidden -> Hidden
step (Hidden value) = Hidden(value + 1)

pub read : Hidden -> Int
read (Hidden value) = value

An importer can infer a local carrier and pass it among compatible operations. It cannot name that carrier in an annotation or global signature:

import carrier as Carrier

main : Unit -> Int
main () = {
    let hidden = Carrier.make(41)
    Carrier.read(Carrier.step(hidden))
}

Transparent matching

A public transparent type exports its complete constructor family. For example, choice.ash exports Choice, First, and Second:

pub type Choice =
    First(Int)
    | Second(Int)

pub sample : Unit -> Choice
sample () = First(42)

Importers can construct and match those constructors, and coverage checks use the complete exported family:

import choice as Choice

main : Unit -> Int
main () = match Choice.sample(()) {
    Choice.First(value) => value
    Choice.Second(value) => value + 1
}

Specification chapters

The specification is split by concern:

  • Lexical structure defines admitted source text, tokens, whitespace, and logical line boundaries.
  • Syntax defines module, import, declaration, expression, and pattern grammar, precedence, and associativity.
  • Name resolution defines module identity, import and export access, lexical scope, and binder identity.
  • Static semantics defines dependency-ordered module checking, exported schemes, entry checking, and expression typing.
  • Elaboration defines how checked modules and surface presentations converge on one linked typed Core program.
  • Dynamic semantics defines values and deterministic evaluation of the generated entry application.

The ash tool documentation describes invocation, module-root configuration, output, diagnostics, and exit status. Those are tool behaviors, not additional language semantics.

Change discipline

Future behavior belongs in design notes and change proposals, not here. A language change updates this specification in the same merge as the implementation and tests that make the new statements true. Partially implemented or intended behavior must not appear here.
