Learn Ash

These chapters form one path through Ash. Work with the programs as you read. Writing a program, predicting its result, and checking that prediction will teach you more than reading the finished code alone. The path is written for beginners; no prior programming experience is assumed.

Before you begin

You need a text editor, a terminal, Git, and a Rust toolchain with Cargo. Follow Prepare Ash to clone the source selected for this edition, build the command-line tool, and make ash available in your terminal. Keep that terminal open while you work through a lesson.

To compare a rejection with its displayed message, run the named checked-in example from the learning-path directory:

cd /path/to/ash-doc/content/learn

The first seventeen lessons use that shared directory for diagnostic commands. The two continuation chapters and the closing lesson state their own lesson-local src directory. The diagnostic commands use checked-in files even when the exploration asks you to edit your own program.ash or main.ash. Follow the shared diagnostic reading notes for the prompt, English output, and source-path convention.

How to work through a lesson

Keep your working programs in a scratch directory outside the checked-in lesson src trees. The chapters build on those working programs; each exercise names a fresh starting point. For a program with imports, keep its entry and required sibling files together in that directory.

Use the same cycle for each program:

  1. Edit the program in your text editor.
  2. Predict the value it will produce.
  3. Run the program with ash.
  4. Inspect the value and type that ash displays.
  5. Explain why the program produced that result.

When your prediction differs from the result, pause. Work through the expressions one at a time, change the program, and run it again.

Learning with an assistant

You can work through every chapter without an assistant. If you use an LLM chat or coding agent, give it the current lesson, your program, and the output from ash. This instruction establishes its role:

Use this lesson, the repository, and the output from ash as evidence. Ask one question at a time. Help me compare my prediction with the result. Use only ideas introduced so far unless I ask to look ahead. Do not give me a finished exercise solution before helping me reason about it.

An assistant can help you examine a program or form a question. Run the program with ash to test what it does.

Contents

  1. An Ash program — produce values with expressions and functions.
  2. Using another source file — connect modules through imports, public declarations, and qualified names.
  3. Using more than one input — supply chained inputs, pause at a partial call, and read function arrows.
  4. Choosing a result — use integer equality, Boolean values, and exhaustive matching to select a result.
  5. Naming intermediate values — make a block’s steps visible with local bindings.
  6. Making values travel together — keep fixed collections of typed values together with tuples and tuple patterns.
  7. Working with text — display, measure, and convert text with String values.
  8. Defining data — name a new type and the constructors for its possible values.
  9. Handling data forms — follow a data definition with patterns and exhaustive cases.
  10. Patterns in depth — name exactly what a value contains with wildcards, nested patterns, and literal patterns.
  11. Following recursive data — follow a self-reference with a recursive function and a stopping form.
  12. The edges of the language — meet the forms Ash declines and the idioms that cover each absence.
  13. Ordering from data — build the natural numbers and comparison from a data definition.
  14. Functions as values — receive, construct, and return function values.
  15. Definitions for many types — reuse functions and data definitions through type parameters.
  16. Module channels — choose which public names cross a module boundary, and re-export them through a facade.
  17. Opaque types — keep a type nameable across a boundary while hiding how its values are built.

Continuation chapters

  1. Generalizing local functions — distinguish local generalization from a fixed function value.

  2. Defining local recursion — use annotated recursive groups and distinguish guarded construction from forcing unfinished data.

Closing chapter

  1. Where Ash goes next — meet interfaces, effects, and scoped resources in small programs, and follow them into the paths that develop them.
