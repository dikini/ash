All design notes

This is proof evidence governed by DN-0033. It defines a candidate annotated control kernel, not current Ash source semantics. It is in progress. No complete safety or compiler-correctness theorem is claimed.

The mathematical companion explains the structural judgments, proof dependencies, and what a full consistency claim would require.

The schematic request boundary is backed by the existing structural judgments. The structural capture and restoration boundary checks the exact cut, outside payload support and well-formed control, then proves capture, actual-prefix resumption, separately admitted disposal and finite ownership accounting. Selected-clause source admission and independent one-shot permissions remain additional premises.

Current proof status

For the current lexical InstallationState, M0 structural resource admission, M1's 32 individual transition families and M2 initial source admission are complete. See complete capture-state construction and initial source admission. M3 now gives combined constructive preservation: every applicable request has a valid successor using source-selected metadata. M4 derives a terminal state or an applicable request from every valid snapshot, provided the immutable operation environment satisfies the admitted builtin cell-signature law. M3 then constructs the preserving event. Fuel-bounded execution retains a valid endpoint and either exhausts its fuel or terminates; raw event traces separately preserve exact owner accounting from an initial ledger. This is not preservation for arbitrary raw annotation choices or a claim that arbitrary raw execution retains source typing. Admitted-program finite execution is exposed by InitialAdmission.Program.finite_prefix; the closed handled-discard fixture is checked by Examples.handled_discard_finite_prefix.

Objective and boundary

Replace the one-shot kernel's named admissibility predicates with structural judgments and prove capture/recomposition plus ownership preservation. The kernel must include recursively live clause captures, exact interpretation selection including builtin blockers, retained resource access, outside pending ticket consumption, armed cleanup, and protected running completion.
