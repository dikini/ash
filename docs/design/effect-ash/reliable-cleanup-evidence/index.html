Retained observations

The normal cleanup tests retain these witnesses:

These tests passed their first run and do not constitute a newly observed behavioral red-to-green correction.

The runtime tests check acquisition charges before publication, capacity reuse, action-start charges, failure before invocation, and deep normal completion/disposal. Actual evaluator-loop traces distinguish failure after a first cell write from failure after a completed inner action; neither replays that action nor starts the outer action during teardown. Successful observation rejects a remaining live cleanup owner.

Measured normal-completion bounds

These are retained test boundaries, not promises about all programs:

  • Acquisition charges 2 + environment.len() before publishing a frame or increasing the live-owner count. One less rejects with both unchanged; exact allowance succeeds twice on fresh machines.
  • Starting the action charges two work units. One rejects before scheduling the action; two succeeds. Running completion still occupies owner capacity.
  • A capacity of one is reused for three successive acquire/complete cycles; a second simultaneous acquisition rejects without adding another frame.
  • The fresh-process small-stack test checks 24 nested cleanup scopes on 256 KiB: capacity 24 completes with 42, while capacity 23 rejects and disposes without raising the stack bound.
  • Core owner validation measures its actual charge, checks one less, and succeeds twice with the exact allowance. Contextual row joining checks every allowance below its measured requirement and two exact fresh retries. Neither test establishes a universal fixed compiler-work formula.

The partial-effect tests measure runtime work at strict markers after a cell write has returned and after the inner action has returned. Each failure run visits the first marker once; only the latter case visits inner completion, and neither visits outer-action start. Repeating a fresh test execution checks determinism, not permission to retry an external release.

Downstream limits to retain

Cleanup establishes an invocation attempt, not termination or successful native release. Foreign partial acquisition and failed native release still require provider-specific rules. No existential package, universal error domain or owner-transfer rule is introduced. Captures retain their own state without a global registry; escaping suspension remains outside this slice.

Arbitrary captured source handlers cannot simply be restored for cleanup: an Int-answer handler with clause (resume ()) + 1 needs the abandoned body's result. Generalizing that boundary requires separate answer/control design. Independent semantic review retained these foreign, proof, existential, suspension and handler boundaries in the completed implementation.
