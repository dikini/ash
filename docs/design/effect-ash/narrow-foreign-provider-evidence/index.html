Native and injected observations

The first-party adapter owns the private pointer and calls C calloc/free. Its six tests include real successful allocation, zeroed bytes, checked access and one release after moving ownership. Root evaluator tests observe calls into that safe adapter and ownership drops. Together these boundaries connect root ownership observations to actual C release; root counters are not presented as direct C-call instrumentation.

Injected null is a separate failure witness, not evidence that the host allocator actually exhausted memory. Normal execution, captured/discarded owners and post-success publication failure use real buffers. Handles contain activation keys, never addresses; retired-key rejection precedes access independently of whether the allocator reuses an address.

The exact CLI fixture prints Success(Success(42)) : Outcome<Outcome<Int>> plus a newline, with empty standard error and exit status zero.

Disposal and failure boundary

The accepted transition distinguishes atomic native refusal from terminal runtime resource failure. The prepared refusal result may be delivered only without further allocation or new observable state; earlier initializer effects remain committed. Insufficient retained disposal capacity is terminal.

The disposal worklist reuses existing environment, captured-frame, type and kind traversals. Eight inline slots handle small pending sets; ordinary disposal may reserve spill storage fallibly. Refusal delivery forbids that growth. Exhaustion preserves a fixed first failure and safely abandons undismantled ownership, reporting incomplete cleanup rather than recursively dropping it or retrying. No source cleanup or recovery traversal is introduced. This does not promise that whole teardown cannot fail.

Each dismantled structural node is consumed once. Environment traversal follows at most two outgoing edges per unique entry; shared entries are dismantled only when their final owner is consumed. There is no repeated graph scan or frame rotation. Existing small-stack tests pass with these traversals.

Independent contract review cleared refusal delivery and fail-stop disposal. Separate Rust review found no additional ownership/disposal defect, but found missing resource details on shared capture and native-request work failures. The subsequent audit also found such sites in cleanup, registration, cell admission and generic application while a native owner can remain live. Those direct paths now retain resource details. Contract re-review found two generic row-helper defects: detected clone reservations could panic, and canonicalization could misreport storage refusal as work exhaustion. The complete runtime row path now passes independent contract re-review, including comparison inside canonicalization and tail membership. Independent Rust quality review and full verification also passed. The bounded writer must retain both a legacy primary reason and the explicit resource cause when they differ; an undetermined storage-reservation cause is not a claimed RAM quota. The structured reporting mechanism handles returned failures from fallible operations; it does not intercept process termination by infallible host allocation APIs.

Verification and limitations

  • 1,214 library tests, 14 CLI tests and 50 native integration tests, including the storage-fault matrices and native-owner source-effect-stop witnesses;
  • cargo check --workspace --all-targets --target aarch64-unknown-linux-gnu --locked.

The merged checkout then passed cargo xtask verify in full. Final status-only documentation changes were checked separately; they change no Rust or Ash code.

Changed Markdown has no new lint findings against the compiler checkpoint; existing overlong lines remain, and table and formal-code line lengths were excluded. Relative file links resolve after artifact cleanup, and referenced specification headings were checked. Final contract and Rust/resource reviews found no remaining findings.

ARM64 compilation is not native ARM64 execution or release conformance. Native tests here ran on Linux x86-64. No other backend or simulated portability fallback is claimed.

A combined recursive native-owner/cleanup witness exhausts checker work before evaluation. In the recursive discard interaction, wrapping the native body in cleanup fn(ignored) { perform Record.digit depth } { ... } reproduces it; using Buffer.length b instead of depth also exhausts work. Removing only that cleanup layer admits recursive native ownership and discard. Separate tests cover cleanup access and mixed ordering. No limit was raised, and this combined case is not claimed admitted.

Library-defined acquisition, a general FFI, files and fallible native close are excluded from this slice. Fixed native free has no recoverable close result; these observations do not generalize that rule to future file providers.
