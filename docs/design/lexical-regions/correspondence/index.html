Lexical region correspondence and assumptions

Development design notes · ash-lang 67c79dd

Informative design work. Proposals and experiments may be incomplete or superseded. Read the language specification for current rules.

All design notes

This report maps the bounded model to the historically matched CP-0025 contract at R1/R2 retention. It supplies R1/R2 evidence rather than language authority or product implementation evidence. Current language rules belong in the specification, including construction dependencies, Core lowering and region execution. The gate and transfer record identifies the exact reviewed inputs.

The aggregate Coherent predicate includes Safe, ServiceContextsSafe and NoReturnedCursors. Its step/trace theorems derive the successor from actual updates and local premises. The model is finite and sequential; ordinary source evaluation, type/effect checking and foreign module contracts supply the explicit assumptions below. Inaccessible physical object records do not impose usable-reference liveness.

ReleaseReady is an explicit current-state conjunction of actual context, usable graph/view, live-child, captured frame and retained provider-view guards. It is not successor-state safety. The same guards are checked before release begins and at normal successful return. Physical validity until the contractually successful release event, freshness/disjointness and reclamation are module assumptions; the model does not prove native memory behavior.

OwnerAvailable is targeted: no source use/new record can touch the owner currently being released. Callback work in a different live region is not globally banned. Provider context views are operational retained state; ordinary inaccessible object bits remain outside that liveness invariant.

Operation correspondence

  • EnterPrepare/EnterLive/abortPrepare preserve the prospective identity and fixed allocator pair; setup equality authenticates the saved preceding selection. No owner is published on aborted preparation. parent and precedingContext have separate roles.
  • Request carries independent owner/extent/alignment metadata. The serviced pending identity, progress/history marker and typed ordinary operands are retained by evaluator/control admission rather than sent to the allocator. Source/Core guardedness and actual value/layout metadata remain local assumptions; this is not a whole compiler/lexical evaluator proof.
  • Supply requires actual fresh registered backing and restores the saved caller; initialization is pending-only; GroupReady handles private cyclic slots without requiring every target initialized during each earlier initializer. cyclic_full_trace includes actual request/supply/init/publication/drop and both bulk closes; cyclic_bulk_retired checks both records.
  • Whole roots retain the usable graph; inline views keep the physical container and the selected part's authenticated dependencies. The outer/younger controls keep inaccessible outer bytes after younger close. Inline views must have been derived/retained legitimately; a dead whole value is not recovered.
  • Calls use current caller selection for subsequent allocation and leave existing closure residency/captures unchanged. CallerPlacement.construction_trace and caller/explicit request controls exercise actual allocation-record construction. Ordinary lexical function application and the validated template/environment mechanism are assumed, not reimplemented by this finite model.
  • Canonical owner service uses saved preceding context and provider cut. suspendService saves an outer request; nested supply/refusal traces restore it exactly. captureFull moves only the owner/service-frame prefix; resume restores it above the resumer return frame. Outside frames and shared objects are preserved.
  • Close cursors are keyed by the unique owner. Captured cursors are dormant and cannot be discarded; actions follow their recorded order. Release return is now atomic with bulk retirement. No pointer/reference alias gets completion ownership.

The finite region extension leaves ordinary source effects and lexical evaluation abstract. operandHistory is an opaque already-performed-effects marker; region transitions do not roll it back or replay it. Internal work/control exhaustion is not an ordinary source allocator refusal and carries no new cleanup guarantee. Source/Core access, cleanup/interpreter compatibility and foreign module guarantees are stated assumptions, never Coherent successor premises. No runtime implementation or proof of a native allocator is claimed.

The model has no numeric range domain or source Int classification. Under integer residency admission, an independent immediate needs no owned record; persistent digits instantiate existing request/supply/initialize/publication and dependency guards. Generic source/Core Scalar-to-Free lowering must not classify unknown Int as independent. Conservative arithmetic admission and faithful Cell/call/request summaries remain compiler correspondence obligations. The existing finite preservation result does not establish these classifications, private immediate-range agreement or arithmetic correctness; this clarification adds no theorem, proof module or changed transition premise.

Operation and assumption readback

This readback compared the finite model with the CP-0025 semantic candidate at a21d0001c34a4ac5a0557e34cfcfb4ea2b1e44a0, especially its explicit lowering, operational contract and R1 handoff. That matched contract/model boundary was retained through PR #146 at aee02227b69fb6cbbd00c23904ffe2a0c7df6924. The correspondence below identifies modeled updates and source/Core assumptions; finite preservation proves neither compiler implementation nor the later closure-creation and integer-residency amendments.

Default and explicit allocation. Implicit construction lowers through the private generated DefaultAlloc handler to RegionAllocate(selected_view, request). using r supplies that explicit default operand. Explicit RegionAllocate(other_view, request) can instead target a different live owner; it does not change the caller's default. In the model, Requirements.owner is the actual request target. ConstructionStep.request and Transition.request check that owner's record, freshness, provider context/cut and targeted availability; they do not require request.owner = heap.selected. Equality is a lowering obligation for default construction, not a generic request invariant. The CallerPlacement controls exercise default placement choices without asserting that every admitted request is implicit. Existing closure records and captures remain unchanged; Transition.call checks usable/available access but is an identity heap/control step, not an implementation of lexical application.

Preparation, backing and local construction. prepare authenticates precedingContext and providerCut against current selection/cut; enter publishes the same prospective region identity with its fixed Association. abortPrepare publishes no live owner. requestStorage retains the pending object, caller context/cut and operand-history marker, then switches to the owner's saved provider context/cut. ReplyAdmitted, fresh-backing admission and supplyStorage check/register the requested owner's backing and restore the caller. Pending-only initialization retains local fields/captures; publication requires the finite ready graph and unused publication history. These checks do not prove physical freshness, disjointness or storage validity. Guarded source initialization and authenticated field/layout metadata remain input obligations.

Context query and cleanup. CP-0025's Unit DefaultAlloc.context () returns a small dependency-bearing RegionView for the actual selection. Core evaluates the cleanup action once, queries that view, and retains both in its ordinary owned cleanup frame. The generated action-local handler answers context with the saved view and forwards allocate q to RegionAllocate(saved_view, q). Neither the action nor younger captures cross the query. The finite Transition.contextQuery checks selected owner and OwnerAvailable, then leaves the machine unchanged: it abstracts the query and does not construct a typed RegionView result. SavedContextsSafe, saved pending/return/captured contexts and ServiceContextsSafe model retained operational dependencies; cleanupActions and close cursors model recorded action identities/order. They do not encode the per-action RegionView payload or generate its two Core handler clauses. Their correct registration, retention and explicit use remain source/Core obligations.

Effects and owner discharge. CP-0025 expands default allocation in source value-function computation annotations before checking, without duplicating an explicit member or changing row-tail/lacks rules. Summaries and Core retain full rows. RegionAllocate includes its explicit operand rows and DefaultAlloc; the enclosing region boundary includes provider evaluation, allocate and release rows unconditionally. Discharge additionally requires a live protecting owner boundary for every targeted invocation. An unknown owner cannot disappear by removing the default effect. The finite model has no effect-row checker; live owners, views and control admission are a correspondence obligation's finite inputs, not a proof of full row expansion, discharge or static/Core validation.

Canonical provider execution and handler compatibility. The accepted transition's primitive invokes the saved allocate member at the supplied owner's canonical interpretation position, using its lexical instantiation and preceding allocation context. providerCut, requestStorage, suspendService/returnService, and the saved/captured frame operations represent switching and restoring that position without overwriting outside control. parent separately constrains owner ordering. Nat cut identities and membership in liveCuts do not prove lexical dispatch or handler compatibility.

In the CP's Console example, H surrounds region setup and J surrounds body construction. Provider Console reaches H for normal allocation and cleanup allocation; J stays in the serviced segment. A cleanup's own Console use may require J. Removing J can admit allocation-only cleanup if H and the owner service survive; removing required H cannot be repaired by another outer same-instance handler. Provider-local handlers retain ordinary precedence. The action-local adapter does not restore removed interpreters. These are exact source/Core cleanup-context and dispatch obligations, not consequences of equal rows, numeric cuts or finite preservation. The finite running-release guards also restrict access to the targeted owner while leaving other available owners usable; they do not establish arbitrary provider code's behavior during close.

Close and assumptions. Recorded cleanup runs before release. ReleaseReady checks current contexts, usable graph/view dependencies, children, captured frames and provider contexts before release and successful return. finishClose combines that return with bulk retirement; the fixed pair is not redirected by a later default. Coherent preservation derives the successor from these local premises. It does not prove release termination, native allocator correctness, lexical evaluation, full static/Core validation or handler compatibility.

Omitted-isolation countermodel (outside the admitted module contract)

Let two live owners A and B share one provider state, with distinct registered backings a and b and valid replies for each owner. Both objects are published; B's object depends only on B. Suppose release(A) incorrectly resets the shared provider's entire validity set from {a, b} to {} and reports success. A's ordinary dependent-use and cleanup checks can all pass, while B's still-live object loses physical backing. Reply-owner/association checking alone cannot exclude this behavior. It violates CP-0025's explicit requirement that successful release preserve other regions. The model's owner-specific closeRegion update preserves B's record because it assumes that contract; it cannot certify this faulty provider. This finite countermodel explains the isolation premise without adding addresses, a native protocol or a new proof framework.
