Functions as values

In the lesson on several inputs, the partial call add 20 produced a function. That function could wait for another integer because functions are values in Ash. Like other values, a function can be given as an input, produced as a result, and associated with a name.

This lets one function describe when another calculation should be used. We will begin with a named function, then remove the name, and finally construct a function that remembers an earlier input.

Giving a function as an input

Suppose we want to apply the same integer transformation two times:

increment : Int -> Int
increment number = number + 1

apply_twice : (Int -> Int) -> Int -> Int
apply_twice transform number = transform (transform number)

main : Unit -> Int
main () = apply_twice increment 40

The first input to apply_twice has type Int -> Int. The parentheses in (Int -> Int) -> Int -> Int keep that whole function type together. After receiving such a function, apply_twice receives an integer and produces an integer.

In the body, transform stands for the function supplied by the call. Predict the value after its first application and after its second. Run the program; Ash reports 42 : Int. Substituting the supplied function explains the two calls:

apply_twice increment 40
increment (increment 40)
increment 41
42

No special call syntax is needed for the function parameter; transform number works like every named function call we have written. A function that receives another function, like apply_twice, is called a higher-order function.

Writing a function where it is needed

If a small function is used in only one place, a separate definition may hide the calculation rather than clarify it. An anonymous function is a function expression without a source-level name:

apply_twice : (Int -> Int) -> Int -> Int
apply_twice transform number = transform (transform number)

main : Unit -> Int
main () = apply_twice (fn(number) {
    number + 1
}) 40

Read the expression inside the parentheses as “a function of number whose result is number + 1.” Ash knows that apply_twice requires an Int -> Int, so the parameter and result are checked as integers.

Predict whether replacing the named function changes either application. Running again produces 42 : Int: the anonymous body adds one at each call. The choice between a named and anonymous function is about explanation: name a function when the name helps the reader or the calculation is reused; keep a short, local transformation beside its use when that is clearer.

Producing a function

A function expression may use a parameter from the surrounding definition. That use remains available after the surrounding call has produced the new function:

make_adder : Int -> Int -> Int
make_adder amount = fn(number) {
    amount + number
}

main : Unit -> Int
main () = make_adder 20 22

make_adder first receives amount. Its result is the anonymous function fn(number) { amount + number }. That function remembers the particular amount from the call that created it; a function value that carries bindings from where it was made is called a closure.

Which input is saved when the function is created, and which arrives when it is called? Predict the final value before running. Ash reports 42 : Int. Trace creation first:

make_adder 20
fn(number) { 20 + number }

Supplying the remaining input continues the calculation:

make_adder 20 22
20 + 22
42

Creating the anonymous function retains 20 without doing its addition. The later call supplies 22, then the body computes the result. This is the earlier partial-call idea written out: creation produces an Int -> Int, and its invocation produces the integer.

A function parameter requires a function

Function types preserve the same boundary as other types. The first input to apply_twice cannot be an integer:

apply_twice : (Int -> Int) -> Int -> Int
apply_twice transform number = transform (transform number)

main : Unit -> Int
main () = apply_twice 2 40

Compare the first argument’s type with the parenthesized input contract. Which value would need to be callable? Run this version from content/learn:

$ ash --message-format human --locale en functions-as-values/src/04-not-a-function.ash
This function argument must have type `Int -> Int`, but has type `Int`.
  --> /path/to/ash-doc/content/learn/functions-as-values/src/04-not-a-function.ash:5:23
5 | main () = apply_twice 2 40
  |                       ^ This has type `Int`.
  --> /path/to/ash-doc/content/learn/functions-as-values/src/04-not-a-function.ash:1:15
1 | apply_twice : (Int -> Int) -> Int -> Int
  |               ^ This function requires an argument of type `Int -> Int`.
  --> /path/to/ash-doc/content/learn/functions-as-values/src/04-not-a-function.ash:5:11
5 | main () = apply_twice 2 40
  |           ^ This is the containing function application.
reason: type.argument

The labels connect the integer argument 2 to the function input Int -> Int in the signature, then show the containing call. Replacing 2 with the earlier increment function supplies a callable value of that type. With 40 as its input, applying the increment twice produces 42. The signature tells us not only how many inputs remain, but whether one of those inputs must itself be callable.

Exercise: apply three times

Start from a fresh copy of src/01-named-function.ash in your scratch directory, keeping increment.

Define a repetition that goes one step further:

apply_three_times : (Int -> Int) -> Int -> Int

Its body applies transform three times, each call’s result feeding the next. First run it with the named increment and the value 39; then replace increment with an anonymous function that adds one. Trace both programs before running them — they should produce the same integer and make three calls to the supplied function.

Calculations as data

A function value carries a calculation that can be used later. A function can receive such a value, call it, or return a new function. An anonymous function describes the calculation at the expression where it is needed, and it may remember names from that surrounding expression.

apply_twice works only with functions from Int to Int, even though its structure does not depend on integers. Our IntList similarly repeats a shape that need not be limited to integer elements. The next lesson asks how one definition can express that independence from a particular type.
