Resume-Required Effect Kernel Evidence

Development design notes · ash-lang 7949b6d

Informative design work. Proposals and experiments may be incomplete or superseded. Read the language specification for current rules.

All design notes

This report maps the retained implementation evidence for Ash's first resume-required effect kernel. It is informative, not normative. The Ash specification alone defines the current language. The milestone closure report records integration into main and final verification status. The historical transition was authorized by CP-0013; this retained report does not depend on that temporary proposal or its execution plan.

Retained boundary

The implementation retains module-owned effect and operation identities, identity-bearing open and closed computation rows, checked requests, exhaustive ordered lexical handlers, and one non-escaping resume capability per clause. Effect Core is one operation-family instantiation of the shared Core substrate. The explicit evaluator moves an ordered frame suffix into a first-order captured continuation and reinstalls it without a Rust closure or copied control.

Programs with no effect syntax retain the uninhabited Pure Core operation family and the predecessor evaluator transitions. An imported but unused effect declaration does not select Effect Core.

Combined corpus closure

tests/fixtures/effects/valid/effect-kernel-combined.ash is the one planned combined case. It contains:

  • a polymorphic open-row relay;
  • Read<Int> and Read<Bool> as two exact instances of one API;
  • a Read<Bool> handler nested inside a Read<Int> handler, forcing the integer request to forward across the nonmatching inner boundary; and
  • exactly one resume in each selected clause, after which the restored inner handler receives the Boolean request.

every_valid_corpus_presentation_has_its_exact_library_and_cli_observation now checks the complete program through both retained entry paths. The library observation is value 42 with type Int, and the exact CLI output is 42 : Int followed by a newline. The open row is retained as the complete row argument of the shared TypeApplication carrier through admission, transformation, independent validation, and erasure. The two exact instances remain distinct, the integer request crosses and later regains the nested Boolean handler boundary, and each selected clause resumes exactly once.

The normative source, typing, elaboration, and one-step runtime rules are in the linked specification. This report records the implementation observations; it does not claim or replace the independent reviews required before transition cleanup or integration.
