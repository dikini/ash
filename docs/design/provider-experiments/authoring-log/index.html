2026-10-01: declaration and instance types

The initial acquisition examples named configuration values without showing their bindings or types. Introducing parameters made the names resolvable but did not define the provider's input-to-state-to-access relationship. The revised typing study makes that relationship a prerequisite for syntax.

The acquisition explanation also treated Sqlite.Connection as a provider designator. The intended role is a resource type definition associating its provider, formal identity, effect interface, and handlers. The instance refers to that type definition and introduces a fresh lexical identity. Type and provider roles must remain distinct in resolution and diagnostics.

Generic arena allocation exposes an existing boundary: effect operations have no operation-local type parameters, and an ordinary handler covers one exact effect instance. A generic allocation method needs a specified interface and handler coverage; shorter source syntax cannot supply them implicitly.

Candidate assistance to evaluate after implementation: show a declared resource family's initializer type, instantiated access type, provided effects, outward effects, and result type in one diagnostic or inspection view. Compare this with reading the declaration and inferred client errors manually.
