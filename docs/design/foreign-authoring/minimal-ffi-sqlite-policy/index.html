SQLite policy for the minimal FFI cases

Development design notes · ash-lang 9a8b73b

Informative design work. Proposals and experiments may be incomplete or superseded. Read the language specification for current rules.

All design notes

Status: superseded checked-host design. These contracts are not implemented by current ffi-ash. DN-0057 records their disposition; DN-0037 records the accepted current foreign-call boundary.

This library contract belongs to DN-0057. It owns the portable SQLite signatures, constants, input and output roles, conversion assumptions and diagnostic rules for the worked cases. The canonical transition table owns outcome precedence and lifecycle transitions for both execution modes. The ABI profile supplies concrete target mappings; platform executor profiles supply launch, storage and containment mechanisms. No Linux layout or source syntax is defined here. These are proposed contracts, not current Ash semantics or implementation authorization.

Copied text/null binding supports repeated statement use and exercises the required transient sentinel. Integer/BLOB binding, alternative prepare/open variants and deferred close are not added by this inventory. This does not remove those operations from the wider DN-0037 copying-binding program. Initialization is host-owned before acquisition; a connection never shuts down shared SQLite state. Threading and initialization configuration must satisfy the serialized group contract.

The sentinel mapping follows SQLite's destructor constants. The bridge materializes the declared typed constant. It never calls it or accepts an arbitrary source integer as a destructor. This bounded sentinel role does not admit general function pointers or callbacks.

Preserve each returned C status exactly, including extended codes. Recognize only operation-appropriate outcomes. Unrecognized error codes remain numeric native failures; do not invent ownership transitions from their names. Impossible success/tag combinations and detected misuse are boundary violations. Record any independently known consumption before quarantine.

Input preparation

Paths and SQL are valid UTF-8 without embedded zero. Append one native zero byte. Paths use the zero-terminated contract; SQL passes the explicit total buffer size including the terminator. Keep the input allocation live until all output interpretation requiring it has finished.

Use flags READWRITE | CREATE and null VFS. This supplies no writable-access or filesystem-confinement guarantee. Accept only a database selected by the host grant or explicit in-memory mode; URI handling is disabled for this binding. Concrete path spelling and storage enforcement belong to executor profiles. See open.

Text binding uses a valid UTF-8, zero-free input and a nonnegative payload byte length, excluding its added terminator, with SQLITE_TRANSIENT. Even empty text has a non-null backing buffer. SQL null uses sqlite3_bind_null. Parameter indices are positive native integers; the native call reports invalid parameter positions. Admission and failed-binding recovery follow L10–L17 in the canonical table. Input storage ends after return under the declared copying assumption. See binding values.

Output storage and acquisition interpretation

Every call's direct return is captured in its native type before conversion. There is no fabricated default return if execution does not return. Slots are valid native storage for the complete call, inaccessible to source code. Initialize db = NULL, stmt = NULL, and tail = NULL before their respective calls. A local publication flag begins false and changes only after admission. Initialization makes storage defined; it does not prove the callee wrote it.

Acquisition outcomes are L1–L9 in the canonical lifecycle table. The distinction between partial failed open, empty successful prepare and failed prepare derives from open and prepare.

On successful prepare, require a non-null tail within the SQL payload through its terminating position. Derive a checked offset while retaining the original allocation; never export the pointer. The unused suffix must contain only ASCII whitespace: bytes 9 through 13 or 32. Reject a second statement or other suffix, including trailing comments after the first statement. This deliberately restricts the wrapper rather than silently ignoring SQL. Empty/comment-only input can still produce the no-statement outcome. On tail/admission failure, finalize a conformingly acquired unpublished statement before releasing its connection dependency. If partial-owner close refuses, retain/quarantine its guard; never report disposal succeeded.

Copied text and lifecycle rules

Use T1–T16 in the canonical copied-text table for null/empty/conversion failures, row-scoped original-kind caching, copy admission and publication. Native conversion refusal is T10; an admitted worker refusal is T14; malformed worker success is T15. Parent capacity failure is T13, independently of encoding. Use L10–L23 for binding/reset/step/native finish and K1–K9 for local scope discharge. A lost session closes locally without a stale native call or invented consumption. These rules are the same on each target; only physical executor mechanisms belong to platform profiles.

Native contracts are documented by SQLite's column access, reset, clear bindings, finalize and close. Binding policy conservatively blocks execution/rebinding after uncertainty even where a native implementation might permit additional operations. A native declaration does not prove adherence to any of these contracts.

Diagnostic copying

Diagnostic codes are direct C integer results. Capture them while the connection is live and before another mutating call. Optional errmsg bytes are borrowed, zero-terminated native storage: null means unavailable. Copy within a configured scan bound before invalidation; absent terminator, invalid encoding or refusal of the separate optional diagnostic allowance yields unavailable text with a reason. Actual runtime allocator/work failure is terminal, preserving the original status and known disposition in reserved control storage rather than promising an ordinary source report. The bound limits scanning but does not prove native readability. Never query an already closed connection or finalized statement. See error reporting. The common exhaustion design specifies the required reservations and report construction.

Evidence

Apply the canonical table's distinguishing traces to both executors. Pair native failures with runtime/worker/parent capacity refusal; observe original status, owner disposition, dependency protection and source delivery separately. Header/target representation checks belong to the ABI profile. Launch and containment evidence belongs to the platform executor profile. A conforming logical outcome does not establish native memory safety or database truth.
